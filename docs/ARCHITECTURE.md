# 留白：基础架构与实现边界

这是自主编写的个人专注工具骨架，没有复制前述六个项目的代码。目标是本地运行、中文界面、以个人主动设定的规则为中心。0.2 增加可编译运行的 macOS 应用管理，真实前台计时、启动次数、正常退出与挑战放行；尚不是可防绕过的成品。

## 1. 模块与依赖方向

```text
apps/desktop/src                    中文界面与应用状态
       │
       ├── packages/core/src        纯规则、计时、统计、退出状态机
       │      ├── model.ts          领域对象与输入校验
       │      ├── rules.ts          配额、时段、循环、强度合并、输入挑战
       │      ├── activity.ts       前台时间归属、空闲与休息
       │      ├── focus.ts          会话与奖励结算
       │      ├── enforcement.ts   保护未保存工作的退出状态机
       │      ├── browser.ts       精细网页策略与允许地址
       │      └── ports.ts         存储 / 系统 / 扩展 / 审批接口
       │
       └── repository.ts
               ├── 浏览器预览 → localStorage
               ├── WKWebView 消息桥 → Swift → JavaScriptCore 规则引擎 → SQLite
               └── Tauri IPC → Rust → 本地 SQLite（跨平台预留）

apps/extension                    Chrome / Edge Manifest V3 扩展
       └── packages/core/browser   网站策略判断
               └── 本机扩展存储 → 内容脚本 → 隐藏元素 / 页面遮罩
```

领域核心不依赖 React、Tauri、浏览器或具体操作系统。系统权限相关能力通过接口注入；UI 不直接执行系统命令。浏览器扩展暂时独立配置，桌面与扩展的 Native Messaging 通道尚未实现。

## 2. 数据模型

| 对象 | 含义与边界 |
| --- | --- |
| Target | 应用/网站的稳定身份。应用使用 bundle ID、可执行文件身份；不用窗口标题作为身份。Steam 示例仅代表 Steam 客户端，不能代表所有游戏进程。 |
| Rule | 每日分钟数、每日启动/导航次数、按星期覆盖、允许时段、连续使用休息、强度、保存宽限期。 |
| Blocklist | 一组 Target；专注会话和循环时间表引用列表 ID。列表成员关系是阻挡范围的权威数据，Rule.listId 仅用于编辑器归组。 |
| Schedule | 一周内循环的限制时段，支持跨午夜与多个列表。 |
| FocusSession | 一次专注的开始/结束时间、项目、列表、强度和最终状态。 |
| UsageInterval | [start, end) 活动片段，记录目标与项目，不保存窗口标题或页面内容。 |
| OpenEvent | 明确的应用启动/网站导航事件。切换到已有应用不会增加打开次数。 |
| Reward | 按自然日给指定目标追加时间额度；当前示例是 B 站。 |
| Task / Habit / Project | 任务、按日打卡的习惯、统计所属项目。 |
| AuditEvent | 会话开始/完成/取消和规则修改的本地记录。 |

当前桌面数据是带版本的单条 JSON 状态快照，SQLite 用 WAL + FULL 同步保证一次写入的原子性。前端保存串行排队，损坏备份被校验拒绝。不会把失败读取替换成空数据。后续性能优化应新增按日期索引的 usage_segments、open_events、break_state、reward_ledger 表，并通过迁移将高频活动从快照移出。当前 Mac 原型合并连续活动片段、状态改变时写入快照。管理开启后可能每秒写一次；长期大量历史仍需迁移到增量表，减少写入和序列化成本。

## 3. 规则语义

- 每日额度默认按 `Asia/Shanghai` 自然日重置。时长 `null` 表示不限，`0` 表示没有可用额度。
- 周规则是完整的当日时长/次数覆盖，未配置的星期沿用默认值。
- 所有窗口左闭右开。周一 22:00–次日 02:00 的凌晨部分归属于周一规则。
- 多个规则冲突时取更严格的限制；系统保护目标优先放行。专注或循环列表的限制独立于单条配额规则开关。
- 打开次数限制仅在 `intent=open` 时判断。第十次打开被允许后，不因为后台持续检查而立刻驱逐；下一次启动才受限。
- 奖励仅增加指定目标当天的时长，不增加启动次数，不绕过限定时段、强制休息或当前专注。
- 自然离开达到休息时长可以清零连续使用；到达休息时间前，不因应用重启而自动解除。Mac 采样循环已持久化 `BreakState`。

## 4. 安全退出状态机

```text
达到规则条件
  → 通知/说明原因
  → Mac 至少 60 秒保存宽限期（规则核心最低 30 秒）
  → 请求应用正常退出
  → 再等待 30 秒
  → 仍未退出：保持提醒，等待当次确认
  → 仅在预先开启 + 当次明确确认 + 进程身份一致时，允许强制结束
```

进程身份必须同时匹配 PID、启动时间与可执行文件，防止 PID 重用误杀。软件无法通用地证明所有应用中的文档已保存，因此不提供“已保证保存”的承诺。Mac 应用现已接通 NSRunningApplication.terminate()，匹配 PID、启动时间、可执行路径和 bundle ID 后发送正常退出请求。强制退出额外要求预先开启和当次确认；默认不会自动强杀。未修改系统网络设置。

严格等级决定“规则能否提前解除”，不意味着系统可以突然杀掉未保存工作的应用。救援入口和业务解除分开：救援恢复输入与系统可用性，留下本地恢复记录；不锁任务管理器、终端或系统设置。

## 5. 后台执行与平台接入

Mac 当前采用一个原生进程：AppKit 管理窗口和菜单栏，WKWebView 显示 React 界面，独立 JavaScriptCore 上下文执行相同 TypeScript 核心。界面窗口关闭后采样循环继续；退出原生进程则停止。没有单独 daemon、登录项或 Windows 适配器。

每秒采样 NSWorkspace 的前台应用和已管理进程、CGEventSource 空闲秒数，监听睡眠、用户会话和锁屏通知。采样只保留已支持应用身份，不读取窗口标题。应用身份白名单包括 B 站 `com.bilibili.bilibiliPC`、小红书 `com.xingin.discover`、微信 `com.tencent.xinWeChat` 和 Steam 客户端。小红书安装检测支持 Wrapper 内的 iPad 应用 plist。

NativeEngine 是活动统计和配额的权威状态。前端保存不能清空统计或覆盖奖励。持久化失败会暂停管理；首次启用先建立当前进程基线，不把已运行应用伪算成新启动。新启动通过 PID、启动时间和 bundle ID 去重；当天第 N 次可以继续用，第 N+1 次触发限制。休眠采样间隔、锁屏及空闲从活动计时中排除。

消息桥只接受本地打包页面主 frame 的固定命令，无任意命令执行入口；导航限于打包的本地页面。挑战在原生引擎校验 30 秒单调时间、理由及固定句子，临时放行 5 分钟，严格/托管不允许放行。严格专注期间拒绝规则、列表和时间表变更以及修改该会话。

后续需要：独立执行进程和开机启动、增量数据库、规则修订号和并发协议、Windows 适配、可选审批服务、浏览器 Native Messaging 同步。当前墙上时间仍决定日历和退出宽限期，未声称可抵抗人为改时钟或本地数据库篡改。

## 6. 中国平台的精细屏蔽

扩展已具备可运行的本地策略原型：B 站首页推荐和动态入口、YouTube Shorts、微博热搜、知乎首页推荐、抖音与小红书整站遮罩。动态页面路由变化后重新应用，禁用后恢复显示。

允许地址先于屏蔽策略评估，按 origin 和路径边界匹配。YouTube 指定视频的查询参数也需一致。`/video/BV123` 不会误放行 `/video/BV1234`，假冒后缀域名也不会被放行。

当前限制：DOM 选择器尚未在各网站最新页面上逐一实测；网站变化可能使其失效。UP 主主页允许地址不会自动识别其全部视频，课程分类识别、B 站短视频入口、搜索诱导推荐需单独补充站点适配与实测。当前遮罩不阻止已经发出的网络请求或后台播放，不能当成严格网络拦截。关闭扩展可以绕过；不宣称防卸载。

## 7. 分级解除与托管

温和模式一次确认即可；摩擦模式要求等待 30 秒、至少 5 字理由和完整输入挑战；严格会话不提供提前取消。Mac 应用解除挑战已由原生引擎审核；网页预览仍是界面流程。系统级防绕过尚未实现。

托管模式只保留 `ApprovalPort`，界面禁用。未来审批需配对设备公钥、一次性 nonce、失效时间、签名验证和防重放；不能用本机“同意”按钮冒充朋友/家长批准。涉及远程通信时应单独选择明确的本地局域网或可选中继方案。

## 8. 隐私与完成度

没有账户、遥测、第三方字体或远程分析。浏览器扩展只有本地 storage 权限与六类站点的内容脚本范围。应用默认保留 90 天历史，启动和修改保留时长时清理过期历史；任务和习惯长期保留。导出/导入必须由用户操作。

## 10. 0.3：历历在目与切回次数

用户明确选择“每次从其他应用切回算一次”。NativeEngine 改为前台访问计数，NSWorkspace.didActivateApplicationNotification 立即触发观测，每秒采样用于补充。后台启动不新增打开记录；同一前台访问重复采样不新增。自身提醒会建立一次返回去重标记，切到其他第三方应用后该标记失效。退出/重启后的首次采样建立基线。上述规则替代 0.2 的进程启动次数语义；旧记录 kind=launch 保留并在界面标记，新增 kind=activation。

新模型：FocusReflection 以 sessionId 关联会话（最多一篇，可编辑）；AppOpenReason 记录文字、时间、目标、来源及可选 eventId/限制原因/放行分钟数；OpenEvent 增加 pending/recorded/skipped 理由状态。专注记录 endedAt 保存实际提前结束时刻，旧取消记录从审计事件恢复结束时刻。

save_reflection、save_open_reason 是有限、经过校验的本机消息命令，成功写入 SQLite 后才返回。普通规则快照不能覆盖原生计数、心得和理由。新字段使用 Schema 默认空数组，旧版数据库与备份兼容；历史清理同时处理心得和理由。前端弹窗由 active→completed/cancelled 状态变化触发，关闭后可在时间线补写。

普通打开理由不是解除限制授权；达到限额时优先显示原有挑战/严格提醒。成功放行时才保存挑战记录，失败不记录成功放行。临时放行次数不增加打开次数。

验证：61 项自动化测试通过，覆盖旧数据迁移、切回计数、提醒返回去重、后台启动排除、成功/失败挑战、心得修改去重、提前结束时间、保留期清理、原生状态保存与重启恢复。界面使用独立预览数据测试，未向用户已有记录添加虚构心得。

## 11. 0.4：每日配额次数与液面

原配额卡片在 dailyOpens=null 时只显示用时，导致时长规则不显示打开次数。独立 QuotaCards 组件现在同时展示两项统计，并移出 App 内嵌组件，避免每秒更新时整张卡片重建。dailyQuota 统一计算当天用时、打开次数、星期覆盖、奖励及剩余额度；与执行核心共用 dailyLimits。

液面优先使用剩余时间比例，仅次数规则改用次数比例并明确标注。无限制不伪造百分比，零额度与超额限制在 0%。测试总数为 67，新增计算测试覆盖秒数、次数、周覆盖与奖励、零/不限/超额、跨日以及原生访问去重后的卡片值。
